# telegram_chats_bot

Telegram-чат с веб-интерфейсом: сообщения, медиа и история хранятся локально, доступ — через браузер.
Поддерживается несколько пользователей (список ID), тёмная/светлая тема и офлайн-расшифровка голосовых
через **sherpa-onnx** (GigaAM v3 для русского, Whisper base для остальных языков).

Проект рассчитан на запуск в Docker: **приложение — это один контейнер**, внутри
Flask отдаёт и веб-интерфейс, и HTTP API (фронтенд не вынесен в отдельный контейнер).
Данные и модели — в volume-ах. Дополнительные контейнеры `local-bot-api` — это
инфраструктура Telegram для больших файлов, а не части приложения; без них
приложение работает с обычным облачным Bot API.

> **Voice Button больше не используется.** Никаких обращений к порту `8931` нет: распознавание встроено
> в приложение и работает на sherpa-onnx локально.

## Возможности

- Веб-интерфейс на Flask + waitress, `http://localhost:8000`.
- Агентский HTTP API на порту `8765` (для автоматизации).
- Мультипользовательский режим: `ALLOWED_USER_IDS`, опциональное автоподтверждение новых пользователей.
- Вложения скачиваются автоматически при появлении в чате; отдельные кнопки
  скачивания в пузырях убраны — скачать можно через правый клик → «Скачать».
- Превью ссылок: YouTube-карточки с встроенным плеером и Open Graph-карточки сайтов.
- Выделение нескольких сообщений, контекстное меню (копировать текст/картинку, скачать),
  подсветка синтаксиса в блоках кода.
- Нативное окно Windows с треем — в папке `windows/` (см. `windows/README.md`).
- Локальное хранилище: SQLite, медиа, аватары.
- Офлайн-расшифровка голосовых: модели скачиваются в volume `models`, движок выгружается из памяти
  после каждого использования (экономия RAM), сами модели остаются на диске.
- Опциональный локальный Telegram Bot API — файлы до 2 ГБ.

## Быстрый старт

Требования: Docker Engine с BuildKit и Docker Compose v2.

```bash
# 1. Конфигурация
cp .env.example .env          # Linux/macOS
# copy .env.example .env      # Windows CMD
# Copy-Item .env.example .env # Windows PowerShell
```

Откройте `.env`, как минимум заполните `BOT_TOKEN` и `ALLOWED_USER_IDS` (см. следующий раздел).

```bash
# 2. Запуск
docker compose up -d --build

# 3. Проверка
docker compose ps
docker compose logs -f app
```

Откройте <http://localhost:8000>. Агентский API доступен на <http://localhost:8765>.

При первом запуске создаются `data/` и `models/`; если модель распознавания ещё не скачана,
в настройках будет кнопка «Скачать».

## Токен бота и ID пользователей

1. В Telegram откройте [@BotFather](https://t.me/BotFather), выполните `/newbot`, задайте имя и username.
2. Скопируйте токен вида `123456789:AAH...` в `BOT_TOKEN`.
3. Напишите своему боту `/start` (или любое сообщение).
4. ID отправителя отображается в интерфейсе в списке пользователей (known users). Добавьте его
   в `ALLOWED_USER_IDS`; несколько ID перечисляются через запятую: `111111111,222222222`.
5. Перезапустите приложение: `docker compose restart app`.

> Telegram запрещает ботам писать пользователям первыми. Поэтому «поиск пользователя» — это не
> глобальный поиск по Telegram, а список тех, кто уже сам написал боту `/start`. Добавить по ID или
> `@username` можно только такого пользователя (или публичный username, который Bot API умеет
> резолвить). Произвольного человека, который боту не писал, добавить и написать ему нельзя —
> это ограничение Telegram, а не приложения.

`AUTO_APPROVE=true` автоматически одобряет новых пользователей — по умолчанию выключено (`false`),
незнакомые пользователи не получают доступ.

## Docker-команды

| Задача | Команда |
| --- | --- |
| Логи приложения | `docker compose logs -f app` |
| Статус и healthcheck | `docker compose ps` |
| Перезапуск | `docker compose restart app` |
| Обновление после `git pull` | `docker compose up -d --build` |
| Остановка (данные сохраняются) | `docker compose down` |
| Полная остановка профиля local-bot-api | `docker compose --profile local-bot-api down` |

`docker compose down -v` удаляет named volume локального Bot API. Данные в `./data` и модели
в `./models` при этом остаются — это bind-mount-ы на хосте.

## Локальный Bot API (файлы до 2 ГБ)

По умолчанию используется облачный Bot API. Для больших файлов можно поднять локальный
`telegram-bot-api` и nginx, который отдаёт эти файлы приложению.

1. Получите `api_id` и `api_hash` на <https://my.telegram.org> (API development tools).
2. Создайте `docker/telegram-bot-api.env` (файл в `.gitignore`, в репозиторий не попадает):

   ```dotenv
   TELEGRAM_API_ID=1234567
   TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
   TELEGRAM_LOCAL=1
   ```

3. В `.env` укажите адреса внутри compose-сети:

   ```dotenv
   TELEGRAM_API_BASE=http://telegram-bot-api:8081
   TELEGRAM_FILES_BASE=http://bot-api-files:80
   ```

4. Запустите приложение вместе с профилем:

   ```bash
   docker compose --profile local-bot-api up -d --build
   ```

`telegram-bot-api` хранит файлы в named volume `telegram_chats_bot-bot-api-data`; контейнер
`telegram_chats_bot-bot-api-files` (nginx:alpine) раздаёт их по `TELEGRAM_FILES_BASE`, поэтому
приложение не обращается к диску Bot API напрямую. На хосте порты опубликованы только на
`127.0.0.1`: Bot API — `8081`, nginx — `8082`.

Локальный Bot API позволяет работать с файлами до **2000 МБ**. Чтобы вернуться к облачному API,
верните `TELEGRAM_API_BASE=https://api.telegram.org` и пустой `TELEGRAM_FILES_BASE`.

## Настройки

Все настройки задаются переменными окружения в `.env` (см. также `.env.example`):

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | — | Токен бота от @BotFather (обязательно) |
| `ALLOWED_USER_IDS` | пусто | Разрешённые Telegram ID через запятую |
| `AUTO_APPROVE` | `false` | Автоподтверждение новых пользователей |
| `TELEGRAM_API_BASE` | `https://api.telegram.org` | Адрес Bot API |
| `TELEGRAM_FILES_BASE` | пусто | База URL файлов; пусто = облако |
| `WEB_PORT` | `8000` | Порт веб-интерфейса |
| `AGENT_API_PORT` | `8765` | Порт агентского HTTP API |
| `AGENT_TOKEN` | пусто | Токен авторизации агентского API; пусто = без проверки |
| `THEME` | `dark` | Тема интерфейса: `dark` или `light` |
| `ASR_ENABLED` | `true` | Включить расшифровку; `false` — движок не загружается |
| `ASR_MODEL` | `gigaam-v3-rnnt-punct` | Модель распознавания |
| `TZ` | `Europe/Moscow` | Часовой пояс контейнера |

В интерфейсе доступны: смена темы, включение/выключение расшифровки, выбор и скачивание модели,
список пользователей и удаление чата.

## Модели распознавания

- **GigaAM v3** (`gigaam-v3-rnnt-punct`) — русский язык, пунктуация, около **225 МБ**.
- **Whisper base** — многоязычный вариант.

Модели скачиваются из интерфейса (Настройки → распознавание → «Скачать») в volume `models`
(в контейнере `/app/models`). После скачивания расшифровка работает полностью офлайн, без внешних
сервисов. Если модели нет, при первом запуске интерфейс предложит её скачать.

Движок распознавания загружается по требованию и **выгружается из памяти после каждого
использования**, поэтому в простое RAM не расходуется; модели при этом остаются на диске.
При `ASR_ENABLED=false` движок не загружается вообще.

## Безопасность

- Веб-интерфейс и агентский API по умолчанию **без пароля**. Не публикуйте порты `8000` и `8765`
  в интернет: доступ должен быть только из доверенной сети, через VPN или reverse proxy с авторизацией.
- `AGENT_TOKEN` включает проверку токена для агентского API. Пустое значение — авторизации нет.
- Секреты храните только в `.env` и `docker/telegram-bot-api.env`; оба файла в `.gitignore`.
- `.env` не попадает в Docker-образ (исключён в `Dockerfile`).
- При утечке токена перевыпустите его в @BotFather.

## Структура проекта и данные

```text
telegram_chats_bot/
├── web_main.py              # точка входа: Flask + waitress (8000) и агентский API (8765)
├── webui/                   # шаблоны и статика веб-интерфейса
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
├── .env.example             # шаблон конфигурации, коммитится
├── .gitignore
├── docker/
│   └── telegram-bot-api.env # ключи my.telegram.org для локального Bot API (не коммитится)
├── data/                    # bind-mount → /app/data
│   ├── messages.db          # база сообщений (SQLite)
│   ├── media/               # вложения
│   └── avatars/             # аватары
└── models/                  # bind-mount → /app/models, модели распознавания
```

`data/` и `models/` создаются при первом запуске и не хранятся в git. Чтобы сделать резервную
копию, достаточно остановить контейнер и скопировать эти каталоги.

## Ограничения Bot API

| Режим | Скачивание | Отправка |
| --- | --- | --- |
| Облачный Bot API | до 20 МБ | до 50 МБ |
| Локальный Bot API (`--local`) | до 2000 МБ | до 2000 МБ |

Облачный режим не требует `api_id`/`api_hash` и подходит большинству пользователей. Локальный
режим нужен для больших видео и документов, но требует отдельного контейнера и места на диске.

## Публикация на GitHub

`.gitignore` уже исключает `.env`, `config.json`, `data/`, `models/`, логи и окружения.

```bash
git init
git add .
git status          # в списке не должно быть .env, config.json, data/, models/
git commit -m "telegram_chats_bot: docker-first web chat"
git branch -M main
git remote add origin git@github.com:USER/telegram_chats_bot.git
git push -u origin main
```

Если `.env` уже попал в индекс: `git rm --cached .env` (и при необходимости перевыпустите токен).
Перед публикацией убедитесь, что в репозитории нет `docker/telegram-bot-api.env` и `config.json`.

## Если что-то не работает

- Логи: `docker compose logs -f app`; статус: `docker compose ps`.
- На Linux при ошибках доступа к `data/`/`models/`: `sudo chown -R 1000:1000 data models`.
- Порт занят: измените `WEB_PORT`/`AGENT_API_PORT` в `.env`.
- Healthcheck проверяет `/api/health`, при его недоступности — `/`.
